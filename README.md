# LetShow · 知行录

**把想法，做成看得见的作品。**

一个以作品为中心的个人项目展厅，把项目背景、实际界面、操作视频、技术栈和实现原理放在同一条浏览路径中。

**[访问在线展厅](https://chenc55.github.io/)** · [浏览全部作品](https://chenc55.github.io/#works)

> 本仓库保存可直接部署的网站静态成品及本说明，不包含 Astro 工程源码，也不包含三个展示项目的业务源码、后台服务或数据库。

## 为什么做这个展厅

项目介绍如果只有技术名词或几张截图，读者往往难以理解：它给谁使用、解决什么问题、如何操作，以及功能背后的实现思路。

知行录把这些信息组织成“看到作品 → 了解背景与痛点 → 看界面和操作 → 理解技术与取舍”的阅读顺序，方便快速浏览，也能进入独立详情页继续了解。

## 展厅提供什么

- **作品浏览与分类**：按网站与应用、桌面工具查看项目；分类保存在网址中，进入详情再返回时能够延续原来的选择。
- **图文项目介绍**：包含项目背景、痛点与对应做法、截图解说、实现流程、技术栈和设计取舍。
- **操作演示**：三个项目分别提供 MP4 操作视频、中文字幕和文字步骤，点击后播放。
- **图片查看与分享**：截图可放大，支持键盘关闭并返回原焦点；项目各有独立链接与分享信息。
- **响应式阅读**：桌面与手机使用同一套内容；保留键盘导航、减少动态效果偏好及无 JavaScript 时的基本阅读能力。

## 展厅的技术栈

| 技术 | 在展厅中的作用 |
| --- | --- |
| Astro | 构建静态页面，共用布局与组件，生成首页、三个项目详情和404页 |
| TypeScript | 为项目内容及分类、图片查看、分享等浏览器交互提供类型约束 |
| Markdown + YAML frontmatter | 维护项目介绍、技术说明、截图、视频和章节资料 |
| 内容集合与 schema 校验 | 在构建阶段核对字段、媒体路径和图库引用，减少缺图、错配与内容遗漏 |
| HTML + CSS | 实现作品网格、两行站名、响应式图文布局、流程图和可见的键盘焦点 |
| 原生 JavaScript、`<dialog>`、`<video>` | 完成分类切换、图片弹窗、链接复制及带 VTT 字幕的视频播放 |
| GitHub Pages | 通过 HTTPS 托管静态成品，无需为展厅运行应用服务器或数据库 |

## 展厅是怎样实现的

### 1. 内容先结构化，再生成页面

项目资料按统一结构维护，既包含卡片上的简短用途，也包含详情中的背景、痛点、图文说明、流程和技术职责。构建时校验必需字段和配图索引，再通过共用组件生成页面，避免为每个项目重复编写整套页面。

```text
Markdown 项目资料 + 已审查图片 / 视频 / 字幕
                        ↓
              内容结构与媒体引用校验
                        ↓
             Astro 布局、组件与静态构建
                        ↓
               HTML + CSS + 少量 JS
                        ↓
                 GitHub Pages 展示
```

### 2. 用少量交互增强静态内容

首页用 URL 参数保存分类，详情页保留返回来源。图片查看使用原生对话框管理打开、关闭和焦点；视频使用浏览器原生控件，配合字幕与文字说明。主要介绍直接存在于 HTML 中，不依赖浏览器先请求业务接口才能阅读。

### 3. 先核验成品，再发布

发布前检查静态文件集合、媒体引用和文件哈希，生成与正式域名一致的分享地址；公开成品只包含网站所需资源。页面使用 CSP 限制资源来源，内联脚本按 SHA-256 白名单放行。GitHub Pages 使用 HTML meta CSP，不将其描述为可自定义全部安全响应头。

## 收录的三个项目

以下技术栈属于各自原项目；它们与展厅本身的 Astro 技术栈不同。这里提供图文和录像，展厅不会启动这些项目的后台服务。

### BS · 岗位技能差距分析与学习规划系统

**作用与痛点：** 面向准备就业的学生，把分散的岗位技能要求、个人自评和学习安排连起来，帮助理解“缺什么、为什么重要、下一步先学什么”。

**技术栈：** Vue 3、TypeScript、Pinia、ECharts、FastAPI、MySQL、SQLAlchemy、Apache Spark / PySpark、FP-Growth。

**实现方式：** 用词典与别名规则整理技能，批量汇总岗位需求及技能共现；固定方向、城市与资料范围后，按需求权重比较自评和目标等级，保留版本快照；规划器展开人工维护的技能前置关系，检查依赖并按可投入时间安排逐级任务。技能覆盖度不是录用概率，共现关系也不直接当作学习前置关系。

[查看图文介绍与操作视频](https://chenc55.github.io/projects/bs/)

### 青衿 · HireFlow

**作用与痛点：** 围绕岗位管理简历与筛选协作，解决材料归属不清、评分缺少依据、HR 与招聘负责人交接难追溯的问题。

**技术栈：** React 19、TypeScript、TanStack Query、FastAPI、PostgreSQL、SQLAlchemy、PyMuPDF、DeepSeek API、Docker Compose、Nginx。

**实现方式：** 上传材料先绑定岗位，PDF 解析保留文本块与页码；独立 Worker 执行解析和评分任务。模型给出逐项评价与引文，服务端回查来源并计算加权结果；报告绑定输入版本，HR 核对回传，招聘负责人另行记录决定，避免覆盖历史报告。引文对应原件不等于经历已经得到真实性认证。

[查看图文介绍与操作视频](https://chenc55.github.io/projects/hireflow/)

### 微语 · WXtool

**作用与痛点：** 面向 Windows 的聊天回顾与分析工具，帮助整理已加载消息的概览、搜索原文并查看上下文，把事实统计与模型推测分别呈现。

**技术栈：** Electron、HTML / CSS / JavaScript、Python、本机 HTTP 服务、Node.js、TypeScript、ONNX Runtime、SQLite。

**实现方式：** **基于 WechatVibe 二次开发。** Electron 承载界面，Python 组织账号、会话与消息读取；前端对已加载消息去重并计算数量、时段与发言比例。主动发起分析时，由模型执行层调用本地 Laya 或已配置的远程 API，SQLite 按账号和分析来源保存结果。远程分析会向配置的服务发送相关上下文，不能把整个工具描述为全程离线。

[查看图文介绍与操作视频](https://chenc55.github.io/projects/wxtool/)

## 展示数据说明

截图和视频使用合成或模拟演示材料。BS 与青衿录像使用实际前端及合成预设接口，青衿评分为 Mock；微语录像使用人工编写的合成聊天，未连接模型。这些材料展示操作与界面组织，不代表真实招聘准确率、学习效果、模型效果或微信版本兼容性。

当前站点保留 `noindex,nofollow`，这是搜索抓取偏好，**不是访问控制**；公开地址及仓库中的展示素材可被访问和保存。
